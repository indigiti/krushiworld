## Subsystem review

- **Pune APMC ingestion:** 19 configured feed slugs across 5 physical market groups; raw report dates, original price units and market identifiers remain separate from commodity fields. Status: source contracts validated; upstream live data and Cloudways collector cron not independently accessed.
- **National AGMARKNET:** collector pagination, atomic snapshots, last-good fallback and API-key secret handling have automated coverage. Status: source integration built but **live all-India feed not proven operational**; production requires `APMC_DATA_GOV_IN_API_KEY`, a successful import and real source-date monitoring.
- **Geocoding/PIN:** opt-in GPS, state/district fallback and a curated geocode importer exist. Only sourced locations are mapped; nationwide geocoding and all-India postcode coverage remain incomplete. Never substitute regional centroids or invented places.
- **Frontend:** English/Marathi/Hindi source-backed labels, shareable market URLs, saved crop watchlists and three themes; no fabricated prices in production. Mobile card redesign is scoped to width <= 690 px. Test fixture rates are intercepted inside isolated Chrome sessions and are never inserted into live storage.
- **Historical intelligence:** SQLite archiver, real data backfill, exact crop/variety/grade/unit constraints and no forecast when observations are missing. Requires server-side PHP SQLite3 and actual historical snapshots.
- **Alerts:** Saved locally and checked while the app is visible/revisited; no unattended SMS/push/email delivery. Old reports are suppressed as of this audit.
- **MSP:** season- and grade-specific official policy reference, not a guaranteed purchase price; needs renewal when policy announcements change. No invented horticultural MSP.
- **Weather:** provider adapter exists but live provider access is unverified; source-stale warnings are intentional.
- **Voice/PWA:** voice is user-triggered, depends on browser speech provider/microphone permission; offline shell caches public static assets, not price APIs. Release must run under HTTPS for service-worker/geolocation support.
- **Admin/security:** protected admin token/cookie, CSRF/origin checks, nonce CSP, secure cookie attributes and public/private release separation reviewed. No complete penetration test of the live server, WAF, PHP extensions or file permissions has been performed.

## Remaining production blockers / follow-ups
**Cannot honestly mark “fully green in production” without these operational checks:**

1. Deploy the new DigiOps artifact, verify live pretty URLs and confirm the v2.0.2 assets and service worker are active on an actual phone; test refresh after existing PWA install.
2. Install/configure the authenticated national AGMARKNET key, execute the initial import and compare counts, individual mandi source dates and provenance with official reports. Never report the import date as market data date.
3. Verify Cloudways cron, writable/persistent private `storage/`, rate/feed health logs, Python runtime, PHP SQLite3 and enough true historical observations for price trends.
4. Validate national mandi/geo coverage and data completeness; source-backed PIN matches and the existing five Pune locations are **not** nationwide geolocation coverage.
5. Connect an authorized, timestamped weather provider if live advisories are required. Unattended notifications need a separate opt-in backend.
6. Perform real accessibility evaluation (keyboard/screen reader, contrast and Hindi/Marathi text) and operational security testing on the hosted site. Automated screenshot assertions are **not** a substitute for those checks.

## Audit conclusion

The repository's simulated deploy and automated code checks are materially stronger after these fixes. Desktop and mobile presentation is now tested from an actual Chromium renderer rather than only static CSS inspection. **Release-ready is distinct from deployed-and-operational:** the final GitHub Actions run is the source of truth for this revision's CI status, and national data freshness/live-device checks must be performed after deployment.
