# APMC Pune Bilingual Naming Layer

## Supported languages

- English (`en`)
- Marathi (`mr`)

The user's selection is stored in `localStorage` as `apmc-language` and mirrored to a SameSite=Lax cookie for continuity. The public market dashboard and Admin/System screen share the same preference.

## Mapping sources

- `config/i18n.json` — UI labels, markets, market slugs, categories, units and fallback commodity names.
- `collector/commodity_map.json` — canonical Marathi/English commodity naming plus aliases and emoji.
- `collector/config.json` — market and category registry with English and Marathi fields.

New collector snapshots include `market_name_en`, `market_name_mr`, `category_en` and `category_mr`. Existing cached snapshots remain compatible because the frontend has fallback mappings.

## Fallback behavior

1. Use the requested language field on the record when present.
2. Fall back to `config/i18n.json` mapping.
3. Fall back to the other language/source label rather than showing a blank value.

Search always indexes English and Marathi commodity, market and category terms, so users can type either language regardless of the active UI language.

## Typography

Marathi mode prefers `Noto Sans Devanagari`, `Nirmala UI` and `Mangal`, then the system UI stack. No font files are bundled.

## Adding a commodity

Add or update an entry in `collector/commodity_map.json`:

```json
{
  "टोमॅटो": {
    "mr": "टोमॅटो",
    "en": "Tomato",
    "emoji": "🍅",
    "aliases": ["Tomatoes"]
  }
}
```

Unknown source names are still retained and served safely.

The public data boundary now resolves commodity names through the verified `collector/commodity_map.json`, alias matching and a conservative transliteration fallback. The market selector is based on canonical `market_id`, not feed slug. See `NAME_NORMALIZATION.md`.
